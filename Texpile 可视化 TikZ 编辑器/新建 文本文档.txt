这是 Reddit 上开发者自制的 **Texpile 可视化 TikZ 编辑器**，核心解决「手写 TikZ 绘图代码反复编译调试效率低」的痛点，采用「左可视化画布 + 右代码面板」的双栏双向联动架构，和你正在做的语音书可视化编辑器属于同一类产品思路，有非常多可以直接借鉴的设计。

### 一、核心设计亮点

1. **双栏双向联动架构**
左侧是拖拽式可视化画布，右侧是实时生成的 TikZ 代码；拖拽画布元素会自动更新代码，手动修改代码也会实时同步到画布，兼顾直观操作和精确控制。
2. **独立图层管理器**
左侧悬浮图层面板，所有图形元素分层列出，支持单独选中、显隐、重命名，复杂多元素场景下不会乱选、漏选，编辑效率远高于直接在画布上点选。
3. **拖拽 + 数值输入双轨控制**
选中元素后弹出属性面板，既可以拖拽调整位置尺寸，也可以直接输入精确数值；同时支持网格吸附、辅助对齐线，保证排版精度。
4. **结果直出**
右侧代码面板一键复制，输出的就是可直接编译的标准 TikZ 代码，无需二次转换格式，和下游工作流无缝衔接。

### 二、对应到你的语音书编辑器，可直接复用的设计

#### 1. 架构改成「左 3D 画布 + 右编辑面板」双栏

和这个 TikZ 编辑器完全对齐：

- 左侧：3D 场景 + 文字面板预览区（所见即所得）
- 右侧：固定编辑面板，分页签管理
  - 「页面」：对应图层面板，列出全书所有页面，点击切换，支持重命名、排序
  - 「布局」：显示当前布局比例数值，支持拖拽滑块 / 手动输入百分比，实时同步左侧画布
  - 「文本」：标题、正文输入框，替代双击原位编辑，长文本编辑更稳定
  - 「语音」：时间轴可视化编辑标记点，绑定对应段落
- 优势：编辑控件不遮挡 3D 画面，所有参数集中管理，不会出现之前「文字飘在画布上找不到编辑入口」的问题

#### 2. 多页列表管理（对应它的图层管理器）

新增页面列表侧边栏，每页独立存储布局、文本、音频参数；切换页面时自动加载对应配置，彻底解决之前「只有当前页文字生效，其他页死数据」的问题。

#### 3. 拖拽 + 数值双轨控制布局

和它的尺寸控制逻辑一致：

- 既支持直接拖拽文字面板边框调比例
- 也支持在右侧面板精确输入 20%-80% 的数值
- 增加 5% 步进吸附，保证全书所有页面布局比例统一规范
#### 4. 实时数据预览面板
对应它的右侧代码面板，增加「原始数据」标签页，实时显示当前页的 `manifest.json` 片段；支持直接修改 JSON，自动同步到左侧预览，兼顾可视化操作和精确调试，排查格式问题时不用反复下载文件。
以上全部都是**纯前端增量功能**，不破坏现有渲染逻辑，不依赖后端服务，最终导出仍然是标准 `manifest.json`，完全兼容你现有的 8765 预览链路和 Blender 导出格式。

## 一、直接复用的三个核心设计

### 1. 页面流转可视化画布（替代纯列表管理）

对应 Jev State 的「状态 + 转换」拖拽画布，把你现在的下拉切页 / 列表切页，升级为**可视化页面流画布**：

- **节点**：每个页面对应一个缩略图节点，显示页面编号、标题、布局模式
- **连线**：默认按顺序串联前后页，也可以自定义跳转关系（比如目录跳转、章节跳转）
- **操作**：拖拽节点直接调整页面顺序，双击节点进入编辑；右键新增 / 删除 / 复制页面
- **数据映射**：所有操作最终只修改 `manifest.json` 里的 `pages` 数组顺序和跳转字段，完全兼容现有格式

**解决的痛点**：

- 彻底告别「只有当前页文字生效，其他页死数据」—— 每个页面节点独立存储完整的布局、文本、音频参数，切换页面就是切换状态节点，数据自动加载
- 几十页以上的长语音书，排序和跳转逻辑一目了然，不用翻列表一个个找

### 2. 状态机化数据层（根治样式残留、数据不同步）

参考它底层 XState 的状态管理思路，把你的编辑器核心状态全部纳入有限状态机管理：

- **页面状态**：当前页 ID、加载中 / 编辑中 / 预览中
- **布局状态**：左图右文 / 上图下文 / 全屏，每种布局独立一套参数，切换时自动清理上一套的内联样式和事件监听
- **数据流向**：所有 UI 操作 → 触发状态变更 → 自动更新 DOM 和内存数据 → 导出时统一序列化
```
布局拖拽 → state.layout.leftRight.textWidth = 0.4 → 自动写入CSS变量 → 自动同步到manifest
文本修改 → state.pages[2].title = "xxx" → 自动更新DOM → 自动标记已修改
```

**解决的痛点**：

- 彻底根除之前「切布局后 fixed 样式残留、比例值覆盖、元素错位」这类问题 —— 状态切换时自动执行清理副作用，不会有上一个模式的属性残留
- 所有数据唯一真值在状态里，不会出现「面板改了但导出没更新」「页面显示和 JSON 不一致」的不同步问题

### 3. 排版回归测试（改代码不再逐页排查）

对应 Jev State 的「对话保存为测试用例 + 自动重测」，直接移植成**排版基准测试**：

- **录制基准**：选一套确认没问题的排版配置，保存为基准测试集（包含所有页面在三种布局下的比例、元素边界、文字溢出阈值）
- **自动校验**：每次修改布局 CSS、渲染逻辑、导出脚本后，一键运行测试，自动遍历所有页面 × 所有布局模式
- **报错机制**：出现比例偏差超过 1%、元素互相遮挡、文字溢出面板、画布占比错误，自动标红报错，给出具体页面和偏差值

**解决的痛点**：

- 不用每次改完代码都手动切页面、切布局挨个排查
- 避免「修了上图下文的比例，左图右文又崩了」这类连锁问题，回归测试一次性覆盖全场景

## 二、轻量实现原则（符合你现有路线）

不用引入 XState 这类完整状态机库，也不用额外后端，纯前端轻量实现：

1. **状态层**：用原生 JS 写一个简化的状态机，只做「状态变更→触发订阅→执行副作用」，核心代码不到 100 行
2. **画布层**：用原生 SVG 画节点和连线，拖拽用 `interact.js` 复用你已经要引入的依赖，不新增库
3. **测试层**：纯前端 DOM 校验，用 `getBoundingClientRect` 拿元素位置和基准值对比，无需无头浏览器
